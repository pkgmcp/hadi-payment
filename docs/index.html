Overview #overview

Hadi Payment merges three open-source payment projects into one maintainable package:

  • bdpayments / laravel-payment-gateway — Laravel-native integration with deep Bangladeshi gateway support plus operational tooling (problems, histories, invoices, reports, notifications, jobs, middleware, admin UI).
  • multipay-php — a broad PHP gateway library for South Asia and beyond.
  • multipayment-php — a superset of 54 generic gateways (Adyen, Amazon Pay, Alipay, Checkout.com, PayPal, Square, Stripe, WeChat Pay, Wise, Worldpay, and more).

Every gateway driver implements the same four-method contract — initialize, process, verify, refund — so switching providers is a one-line change.

On top of the merged drivers, Hadi Payment ships a country catalog (src/Data/gateways_by_country.php) listing payment gateways for all 195 countries — a minimum of three per country and 1900+ unique gateways (27k+ entries) in total, generated from the master gateway database in scripts/catalog/. Long-tail gateways are served by config-driven generic drivers (redirect, REST API, mobile money, bank transfer, card, crypto, wallet, virtual card), while the most popular gateways keep their full concrete integrations — ~70 gateway slugs resolve to concrete drivers via scripts/catalog/drivers.php. Every country also carries a curated top list of 4-5 gateways spanning mobile money, card, bank transfer and virtual-card rails (CountryCatalog::topGatewaysFor()).

Installation #installation

composer require hadi/hadi-payment

Publish the configuration, migrations, and assets:

php artisan vendor:publish --provider="Hadi\Payment\HadiPaymentServiceProvider" --tag="hadi-payment"
php artisan migrate

Available publish tags:

  • hadi-payment-config — publish config/hadi-payment.php
  • hadi-payment-migrations — publish the database migrations
  • hadi-payment-views — publish the Blade views
  • hadi-payment-assets — publish the web assets

The service provider auto-registers (Laravel package discovery). Facades HadiPayment and PaymentGateway are registered automatically.

Configuration #configuration

All settings live under config/hadi-payment.php. Gateway credentials use HADI_* environment variables, e.g.: 

HADI_BKASH_APP_KEY=your-app-key
HADI_BKASH_APP_SECRET=your-app-secret
HADI_BKASH_USERNAME=your-username
HADI_BKASH_PASSWORD=your-password
HADI_BKASH_SANDBOX=true

HADI_NAGAD_MERCHANT_ID=your-merchant-id
HADI_NAGAD_MERCHANT_PRIVATE_KEY=your-private-key
HADI_NAGAD_PUBLIC_KEY=your-nagad-public-key

Quick start #quickstart

Low-level array API

use Hadi\Payment\Facades\HadiPayment;

// Initialize a payment (camelCase and snake_case both accepted)
$result = HadiPayment::initialize('bkash', [
    'order_id'   => 'ORDER-123',
    'amount'     => 150.50,
    'currency'   => 'BDT',
    'callbackUrl'=> route('payment.callback', ['gateway' => 'bkash']),
]);

if (($result['status'] ?? '') === 'pending_user_action') {
    return redirect($result['redirectUrl']); // or render $result['paymentRequest']
}

High-level service with PaymentResponse

use Hadi\Payment\Facades\HadiPayment;

$response = HadiPayment::initializePayment('bkash', [
    'order_id'   => 'ORDER-123',
    'amount'     => 150.50,
    'currency'   => 'BDT',
    'callbackUrl'=> route('payment.callback', ['gateway' => 'bkash']),
]);

if ($response->success) {
    return redirect($response->redirectUrl);
}
return back()->with('error', $response->message);

Verify a payment

$status = HadiPayment::verify('nagad', [
    'orderId'            => 'ORDER-123',
    'gatewayReferenceId' => 'NAGAD_CALLID_...',
]);

Refund a payment

$refund = HadiPayment::refund('bkash', [
    'paymentID'    => 'TRX12345',
    'amount'       => 50.00,
    'reason'       => 'Customer requested refund',
]);

Custom gateways

app('hadi-payment.manager')->registerGateway('mygw', MyGateway::class);
// or via config:
// 'gateways' => ['mygw' => ['class' => MyGateway::class, ...]]

Contract

interface PaymentGatewayInterface
{
    public function initialize(array $data): array;
    public function process(array $data): array;
    public function verify(array $data): array;
    public function refund(array $data): array;
    public function isConfigured(): bool;
}

Countries #countries

The package covers all 195 countries (193 UN member states plus Vatican City and Palestine). Each country lists its relevant payment gateways — local leaders (bKash, Nagad, M-Pesa, Paytm, Mercado Pago, iDEAL, PIX ...), regional gateways, and global PSPs (PayPal, Stripe, Payoneer, 2Checkout, Wise, ...) — generated from the master gateway database in scripts/catalog/.

Query the catalog through the CountryCatalog service, the GatewayFactory::getCatalog() method, or the helpers:

use Hadi\Payment\Facades\HadiPayment;
use Hadi\Payment\Services\CountryCatalog;

$catalog = app(CountryCatalog::class);

$catalog->count();                 // 195
$catalog->countries();             // ['BD' => 'Bangladesh', 'US' => 'United States', ...]
$catalog->gatewaysFor('KE');       // [['key' => 'm-pesa', 'name' => 'M-Pesa', ...], ...]
$catalog->findGateway('bkash');    // country + display metadata
$catalog->driverFor('mtn-momo');   // MobileMoneyGateway::class

// Helpers
get_countries();                    // ISO2 => name
get_country_gateways('BR');        // top gateways for Brazil
get_gateway_country('paytm');      // gateway metadata (India)

// The factory registers every catalog gateway automatically
HadiPayment::isGatewaySupported('mtn-momo');  // true
Catalog gateways are configured through the HADI_<GATEWAY>_* environment convention (e.g. HADI_MTN_MOMO_MERCHANT_ID, HADI_MTN_MOMO_ENDPOINT) when no explicit block exists in config/hadi-payment.php. Concrete drivers such as bKash or Stripe keep using their dedicated configuration blocks.

Security #security

  • No secrets in code or logs. Every log entry passes through sanitizeForLogging().
  • Payload integrity. Payment forms may include payment_hash + amount; the security service verifies before processing.
  • Replay / CSRF protection. Nonce verification on payment form submissions.
  • Rate limiting. Per gateway/IP/user-agent budgets with configurable windows and 429 responses (RateLimitMiddleware).
  • Webhook authenticity. WebhookSignatureMiddleware + signature verification before mutating state.
  • Transport. Outbound TLS with peer verification (relaxed only for sandbox).
Hadi Payment is not a PCI-DSS-certified processor. Keep card data handling on the gateway's hosted pages; never log or persist raw card details.

Events & webhooks #events

Events

Webhooks & callbacks

Routes are exposed under the configurable hadi-payment prefix and accept {gateway} segments (alpha-numeric constraint). Validate the signature, verify the transaction, and persist the webhook/callback payload before updating payment state to stay idempotent.

Architecture #architecture

Laravel app
   │  Facades / helpers / DI
   ▼
Hadi\Payment\HadiPayment  +  Services\PaymentGatewayService
   │
   ├──▶ Factories\GatewayFactory      (60+ drivers + aliases)
   ├──▶ Services\PaymentManager       (normalization + PaymentResponse)
   ├──▶ Services\PaymentValidator     (strict payload checks)
   └──▶ PaymentProcessor / PaymentGateway (HTTP core, sanitize, isConfigured)
          └──▶ Concrete gateways (BkashGateway, StripeGateway, ...)

Cross-cutting Laravel layers:

  • Models — Payment, PaymentLog, PaymentRefund, PaymentHistory, PaymentProblem, PaymentProblemComment, Invoice, InvoiceItem.
  • Services — Security, Logging, History, Reports, Invoices, QR codes, AI-agent heuristics.
  • HTTP — Payment, QR code, report, and admin controllers; security, rate-limit, webhook-signature, and gateway middleware.
  • Jobs / Notifications / Events — queued refunds, mail + database notifications, domain events.
  • Migrations — 8 tables, with a free-string gateway column.

Overall completeness: 100% — every code, wiring, documentation, and release-prep item is complete in-repo. The only remaining steps are external distribution actions (Packagist publication, community review) documented in docs/RELEASE.md. Quality gates: 180 PHPUnit tests / 4682 assertions green, PHPStan level 5 zero errors, PHPCS PSR-12 zero errors, php -l clean, composer validate valid.

Known limitations: the 1900+ gateway catalog is generated from scripts/catalog/ with regional scoping approximating real availability; long-tail gateway drivers use config-driven generic flows and many legacy drivers ship deterministic mock HTTP responses behind commented-out live calls — live API verification needs real credentials per gateway.
